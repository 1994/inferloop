# ADR-0005：CUDA 架构以调优、换 kernel、多模型和版本兼容为目标

- 状态：采用
- 日期：2026-10-31
- 修订：[ADR-0004](0004-performance-first.md) 的执行顺序与“暂缓新增模型家族”

## 背景

kernel 已搬入 `infer-cuda-kernels`（PR #129），但 host 仍是隐藏的内部 compiler：kernel 选择写在录制路径里，同一算子有多条 lowering，每个算子族各有一套调优，host 离不开 cuTile。

同时 CUDA 越权持有 engine 的决策：页账本、准入、推测策略都在 backend 内部，设备时间不上报。engine 的契约因此在 CUDA 上不起作用。继续优化公共分层解决不了这两个问题，继续只优化算子也解决不了第二个。

ADR-0004 把执行重叠定为 P0，并要求先建立 GPU 空泡测量。这项测量至今没有落地，因此 depth 2 的收益没有依据。第二 flight 的预算也缺少可靠账本。

ADR-0004 暂缓新增模型家族。但如果没有第二家族作为验收，lowering 收口就无法证明有效。

## 决策

1. **架构工作的目标是四件事：** 性能调优更方便、kernel 更容易更换、新模型更容易接入、CUDA 版本兼容更容易。方案见 [CUDA 架构收口方案](../plans/engineering/cuda-architecture.md)。
2. **不新增层，做两件事。** 收口 CUDA 内部的 kernel 选择、lowering、调优框架和 host 对 cuTile 的依赖；把时间、准入、页和推测决策交回 engine。边界规则是设备事实归 CUDA，决策归 engine。现有 SPI 可按需调整，但不新增 IR、backend 或第二套容量接口。
3. **算子收口和职责归还都是主线，容量优化是性能线。** 是否归还职责不由性能测量决定。架构资源优先投入主线；C1 的性能工作继续，但新路径必须先有 Plan，CUDA 不新增私有账本。
4. **修订 ADR-0004 的顺序。** 执行重叠不再固定为最高优先级，按需增长与 depth 2 的先后由空泡和显存分项测量决定。默认先按需增长，理由和规则见方案第 5 节。
5. **修订“暂缓新增模型家族”。** 允许用微型 fixture 的第二家族做架构验收；这不代表扩大正式支持范围。正式接入新家族仍让位于上述工作。

ADR-0004 的其他决策不变：AOT 主线、数值与质量合同、验收要求。

## 后果

- 主线要改动 88 个以上 host 文件和热路径，风险最高的是单一 lowering。靠分批迁移、13.x 逐位对照和棘轮控制。
- 页账本迁到 `infer-state` 要跨 engine 与 backend 改动，需与 C1 排窗口；第一步只换所有者，保持预付语义，可用逐位对照判定。
- 第二 flight 落地时间可能晚于 ADR-0004 的预期；如果测量显示空泡占主要份额，顺序会提前。
- kernel 指纹改为内容身份时要处理现有 tuning 缓存的迁移或失效。
- 接入 `completion_timing` 会改变 CUDA 调度结果，需要配对验收。
