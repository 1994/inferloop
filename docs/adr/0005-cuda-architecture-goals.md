# ADR-0005：CUDA 架构以调优、换 kernel、多模型和版本兼容为目标

- 状态：采用
- 日期：2026-10-31
- 修订：[ADR-0004](0004-performance-first.md) 的执行顺序与“暂缓新增模型家族”

## 背景

kernel 已搬入 `infer-cuda-kernels`（PR #129），但 host 仍是隐藏的内部 compiler：kernel 选择写在录制路径里，同一算子有多条 lowering，每个算子族各有一套调优，host 离不开 cuTile。继续优化公共分层解决不了这些问题。

ADR-0004 把执行重叠定为 P0，并要求先建立 GPU 空泡测量。这项测量至今没有落地，因此 depth 2 的收益没有依据。同时，页账、时间账对 CUDA 不准：`completion_timing` 未实现，页按 capacity 预付，所以第二 flight 的预算也缺少可靠账本。

ADR-0004 暂缓新增模型家族。但如果没有第二家族作为验收，lowering 收口就无法证明有效。

## 决策

1. **架构工作的目标是四件事：** 性能调优更方便、kernel 更容易更换、新模型更容易接入、CUDA 版本兼容更容易。方案见 [CUDA 架构收口方案](../plans/engineering/cuda-architecture.md)。
2. **公共分层不动。** 收口范围是 CUDA 内部的 kernel 选择、lowering、调优框架和 host 对 cuTile 的依赖。
3. **分主线和性能线。** 架构资源优先投入主线；C1 的性能工作继续，但新路径必须先有 Plan。
4. **修订 ADR-0004 的顺序。** 执行重叠不再固定为最高优先级，KV 与 depth 2 的先后由空泡和显存分项测量决定。默认先 KV，理由和规则见方案第 4 节。
5. **修订“暂缓新增模型家族”。** 允许用微型 fixture 的第二家族做架构验收；这不代表扩大正式支持范围。正式接入新家族仍让位于上述工作。

ADR-0004 的其他决策不变：AOT 主线、数值与质量合同、验收要求。

## 后果

- 主线要改动 88 个以上 host 文件和热路径，风险最高的是单一 lowering。靠分批迁移、13.x 逐位对照和棘轮控制。
- 第二 flight 落地时间可能晚于 ADR-0004 的预期；如果测量显示空泡占主要份额，顺序会提前。
- kernel 指纹改为内容身份时要处理现有 tuning 缓存的迁移或失效。
- 接入 `completion_timing` 会改变 CUDA 调度结果，需要配对验收。
